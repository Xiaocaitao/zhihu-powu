## 2026-09-14 第二批实施证据（模块按原始文档补齐）

契约与领域规则

- 13 项工具按第 5 节字段契约重写：记录列表/详情联合、`kinds`、游标与本周范围、项目与材料引用、版本前提、面试目标三态（岗位/能力/项目）、单题或整场反馈。
- 记录修正与撤回保留历史修订（`ei_record_revisions`）；材料或能力变化后旧评估标记 `stale`，能力卡片显示“需要重新评估”，不再由记录数量推断掌握度。
- 阶段复盘只依据范围内记录；范围内没有记录时直接拒绝生成，不输出空结论。生成结果中的引用必须能追溯到所提供记录或材料原文（`validateCitations`）。
- 面试状态机含 `preparing / active / completed / ended_early / preparation_failed`；只接受当前题、原文保存、同题重复提交幂等、改写被拒；答完全部题目或提前结束都会生成整场报告；生成失败时保留会话/回答并给出 `recovery`。

持久化与并发

- 应用层每次从仓储恢复状态，短事务内保存业务对象与 `ei_operations` 幂等记录；生成调用在事务之外执行。
- 面试以“整场一次事务”保存（表头、题目、回答、逐题反馈、报告），并保留同场题目复合外键；真实测试覆盖并发作答只推进一次、串场引用被拒、保存失败整体回滚。
- 迁移新增 `008/009/010/011`：同场题目约束、共享能力目录、记录详情与修订、聚合 JSON 文档（编号已避开 main 新增的学习计划 `006/007`）。

跨模块与生成

- 外部查询统一走 `ports.ts`：`createEvidencePorts` 适配 Learning 任务/阶段、Career 岗位要求、Profile 背景、Knowledge 材料、Shared Skills 能力标识；全部通过来源模块的查询接口，不读取他表。
- 生成端口默认由 `LlmInvoker` 驱动（`src/llm/doubao.ts`），未配置模型时返回 `DEPENDENCY_UNAVAILABLE`；确定性替身仅在测试或显式 `EVIDENCE_GENERATION=mock` 时启用。
- 主原型两个页面改为调用真实接口：学习记录页（本周时间线、单条详情、评估入口、复盘、能力证据）与模拟面试页（开始/恢复、作答、逐题反馈、结束、报告、历史）。
