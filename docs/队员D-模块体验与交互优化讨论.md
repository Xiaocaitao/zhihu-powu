# 学习记录与模拟面试：交互定位与体验优化讨论

本文回答三个问题：现在这两个模块的做法是否合理、是否偏离最初需求、市面优秀产品怎么做，并给出建议。结论先给：**方向没偏，但主页面把所有动作都跳去对话窗口是偏离的；模块实现本身还有一批体验差距值得补。**

## 1. 对照最初的需求文档

需求文档定义的是**双入口**模型，不是单一入口。

| 需求条目 | 原文要点 | 定位 |
| --- | --- | --- |
| FR-01 | 打开学习记录页可看本周记录、切换时间范围、按类型/任务/能力筛选、查看详情与材料 | 页面负责看与管理 |
| FR-02 | 用户可以通过首页对话记录学习，也可以补充已有记录的成果材料 | 对话负责捕捉，页面负责补全 |
| FR-03 | 补交材料、修正时间/用时/描述、撤回、旧评估标记待重评 | 页面负责维护 |
| FR-06 | 点击“生成复盘”或在对话中指定时期、阶段 | 两种入口都要有 |
| FR-09 | 页面刷新、离开或对话中断后可找回会话与当前题目 | 页面必须能独立恢复 |
| FR-10 | 建议转入学习计划时由主 Agent 联动 Learning Plan 并展示实际处理结果 | 跨模块动作由 Agent 协调 |

技术契约第 10.1 节写明：页面动作应映射到应用方法，“页面写操作与 Agent 使用相同应用方法、Schema、身份校验及幂等语义”；第 10.2 节才把主 Agent 注册、事件与主页面集成列为队长职责。

判断如下：

- 页面直接调用模块接口是原设计的一部分，**不算偏离**。
- 偏离的是现在主页面的做法：`public/index.html` 里的 `growthPrompt()` 把“开始面试、提交回答、记录学习、读取证据、生成复盘、读取计划”全部改成跳会话页并填入提示词。页面因此退化成提示词入口，用户拿不到 FR-01/03/09 要求的页内查看、修正与恢复。
- 原型页 `public/learning-platform-prototype.html` 一开始就是页内直连，方向与契约一致。

## 2. 市面产品怎么做（调研摘要）

用仓库自带的知乎检索调研，原文链接附在每节末尾。

### 2.1 模拟面试

- 纯聊天式面试被判为“陪练，不是面试官”：缺标准（考什么、怎么判）、缺流程、缺目标对齐，会出现给应届生问资深执行者问题的层级错位。行业解法是“数据叠加 + 流程化 Agent”——JD 到能力映射、阶段模板、评分 Rubric、真题语料，配合推理-反思闭环，做到题目更贴合、追问更像人、评分可复盘、建议能落地。Injob AI：https://zhuanlan.zhihu.com/p/1944431047979831329
- 岗位与简历定制是标配，横向评测的差异点集中在岗位自定义、简历关联、连续追问、结构化复盘、可执行的改进计划。https://zhuanlan.zhihu.com/p/2071976345660289085 、https://zhuanlan.zhihu.com/p/2070181538130555637
- 反馈必须落到具体点，用户认可的是“第三问缺少产业链上下游视角”这类可立即改进的判断，而不是“表现很好”式空话。https://zhuanlan.zhihu.com/p/1977685243193496860
- 闭环是训练→评估→改进→再训练，报告给出薄弱项并推荐二次训练。https://zhuanlan.zhihu.com/p/2026742932061918113

### 2.2 学习记录与复盘

- 字段越多越没人用：一个家长自建错题系统做了 9 字段加 AI 批改和积分，结果孩子几乎零使用，上传者全是家长；复盘结论是把字段砍到 5 个甚至整卷拍照即可，别做“理想中用户会用的系统”。https://zhuanlan.zhihu.com/p/2076259268966334976
- 降低启动成本比激励更重要：有效做法是自动带入昨天内容、模板化、清单勾选，而不是逼用户回忆填写。https://zhuanlan.zhihu.com/p/2066914828539766059
- 被打断后的恢复比连续打卡重要：漏学一天后用户往往直接放弃，好的设计是识别未完成、区分必修与顺延、按剩余时间重排节奏。https://zhuanlan.zhihu.com/p/2075946946280288316
- 完成率不等于学习效果：打卡、看完视频、提交练习都不等于掌握，要把任务完成、练习结果与知识点表现关联起来。同上链接。

## 3. 我们现在的差距

### 3.1 偏离项（必须改）

1. 主页面所有成长动作跳对话，违反第 10.1 节的页面动作映射，用户无法在模块内完成任务。
2. 页面缺少标准可见性：面试页不显示本场能力范围与评价维度，报告只有结论没有依据维度，与“陪练 vs 面试官”的市场结论相悖。

### 3.2 体验差距（建议改，但不改契约）

1. 面试目标靠手填 ID，应该改成下拉选择：岗位来自 Career 岗位列表，能力来自共享能力目录，项目来自本模块项目。
2. 报告缺少“再练一场”入口，市场把训练→评估→改进→再训练当闭环；可按薄弱项开新的独立会话，符合 FR-07。
3. 追问按契约首版不做，但可以在逐题反馈里补一段“如果被追问，你应该准备什么”。
4. 记录表单过重，接近“9 字段错题本”的坑；建议拆成轻量记录（做了什么加用时）与后续补全。
5. 时间线只是陈列，后端已算出待确认关联、缺失信息、需要重新评估的证据，页面应把它们聚合成本周行动项。
6. 中断恢复没有面向用户表达，应该明确显示上次练到第几题与下一步。

## 4. 建议的优化顺序与边界

第一批，只改本模块、页内闭环：

1. 主页面把模拟面试与学习记录的动作改成直连 `/api/evidence/*`，不再跳会话，保留一个显式“问 Agent”入口。
2. 面试页加训练范围下拉、当前题与进度、考察能力标签、逐题反馈、整场报告、刷新恢复、按薄弱项再练一场。
3. 学习记录页加轻量记录与补全、时间段/类型/能力筛选、详情、修正、撤回、评估、复盘，顶部加待补材料与待重评证据的行动区。

第二批，需要其他模块配合：

1. 学习计划读取按钮改直连，`GET /api/growth/learning` 已存在；计划反馈这类写操作等成员 C 提供接口或继续走 Agent。
2. 把复盘或面试建议变成学习任务，仍由主 Agent 联动 Learning Plan，本模块不直接建任务。
3. 画像页与职业规划页属于成员 A/B，不在本次范围。

第三批，后续扩展先记录不做：自动追问与压力测试、跨场次趋势分析、语音与多模态表达评估。

## 5. 待确认的问题

1. 入口边界：模块内动作页面直连、跨模块动作走 Agent，这个划分是否认可？
2. 首版是否确认不做自动追问，只在反馈里提示可能被追问的点？
3. 学习记录是否改成轻量记录加后补材料的两步式，还是保持一次填完？
4. 面试目标是否改成下拉选择，并加按薄弱项再练一场？
5. 是否允许直接改主页面 `public/index.html`，还是只产出替换代码交给队长？
6. 这些改动是否先同步写进需求文档与技术契约的体验优化小节，再动代码？
