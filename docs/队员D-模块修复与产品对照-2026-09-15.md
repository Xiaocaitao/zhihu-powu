## 产品参考及建议

以下来自官方公开页面的功能说明，未登录体验付费功能；产品宣传不等于效果验证。

| 参考 | 官方说明 | 本项目采用的方式 |
| --- | --- | --- |
| [Yoodli](https://yoodli.ai/) | 自定义训练对象和目标，开始角色练习，AI 追问，查看内容、表达和进步反馈；支持重复练习 | 面试页面完成选范围、作答、反馈、报告和再练一场。主 AI 可以发起，但不承担面试表单交互 |
| [Mahara](https://mahara.org/) | 通过活动证据、个人反思和背景构建学习档案，关联能力或评估要求；可以对接学习管理系统进行评阅 | 先保存学习事实及材料，再做明确标准下的评估；记录、评估和学习计划各有归属 |

建议沿用当前视觉风格，把改进重点放在完整流程上。手填项目只作为本场面试背景，不自动生成一条“已完成项目”记录。学习记录可以没有项目；岗位只用于用户主动选择的评估标准，此边界已由负责人确认。

后续可讨论：基于本题回答追问、逐题重练、把报告建议提交给主 AI 请求调整计划。追问需要扩展当前固定题单、并发和恢复契约，不能仅在页面插入题目；建议转计划需要用户明确表达意图后由主 AI 调用 Learning，首版不自动写任务。

## 与其他模块及主 AI 的关系

| 来源/去向 | 行为 | 约束 |
| --- | --- | --- |
| Career → 面试/评估 | 查询用户可访问的岗位及要求 | 本模块不改变目标岗位；岗位评估依赖失败时明确报错 |
| Shared Skills → 两页面 | 获取能力标识和名称 | 不根据岗位或项目名称制造技能 ID，不将资料缺失推断成掌握 |
| Profile → 面试 | 已提供的基础作为生成背景 | 缺失不编造；不替 Profile 写画像 |
| Knowledge → 证据 | 读取已授权材料的内容和可用状态 | 未读取材料不能称为已核验 |
| Learning → 时间线/复盘 | 查询来源事实与阶段信息 | 阶段测试、任务状态修改和计划调整不归本模块 |
| Evidence → Career/Profile/Learning | 提供已保存事实、评估与限制 | 不将记录条数当作掌握度，不把面试表达当成项目实操 |
| 主 AI → Evidence | 明确用户意图后调用相同的 13 项模块能力 | 写入成功后切页面；失败不误跳。面试用返回 ID 定位具体会话 |
| 页面 → Evidence | 公开 HTTP 路由直接调用能力 | 页面内操作不转到主聊天窗口；不重复维护另一套生成逻辑 |

## 已修复

- 模型传输实际发送 JSON Schema；生成端解析 JSON、校验结构、约束题量并最多修复重试一次。未知分类、越界技能保持拒绝。
- 学习记录主导航调用新版初始化；项目字段有静态 HTML，条件隐藏规则限定在本模块，避免 display:grid 覆盖 hidden。
- 已有项目与新项目输入互斥；已有项目成果保存本次个人贡献，未说明时标记待补。
- 项目选择展示后端项目名称，不从某次成果标题推测，也不被时间线分页和时间筛选截断。
- 无项目可保存学习活动；记录详情可选择一般能力标准或岗位标准评估。
- 面试准备/失败/结束后禁止提交回答；出题失败可重新生成，报告失败可重试生成报告。
- 查看历史具体会话，刷新恢复，并从服务器返回的范围、难度和重点创建下一场。保留失败历史与原始回答。
- 提交期间锁定按钮；网络结果不确定时复用写操作标识。新场清空旧输入。
- 本周复盘范围使用服务端返回的时间范围；进入记录页加载保存的能力评估和复盘。
- 主 AI 的 Evidence 业务失败识别和具体面试 ID 导航；其他工具原有事件字段兼容。

## 手动页面验收

运行 `node scripts/evidence-preview.ts`，打开日志中的根路径 `/`。预览使用内存仓储和模拟生成，停止进程后数据消失；不要将其用于生产验证。可设置 `PREVIEW_FAIL_FIRST_INTERVIEW=1` 来验证首次出题失败的恢复。

1. 首次进入学习记录：能力、项目选择正常加载，无项目可保存活动，实际用时可留空。
2. 项目成果 → 手动填写项目：填写目标及本次贡献后保存；再选已有项目保存另一条成果，不能重复要求新项目标题，也不能丢失本次贡献。
3. 打开记录详情：选岗位标准评估；岗位不可用时应明确失败，一般能力标准仍可单独选择。
4. 面试 → 我的项目 → 手动填写：填写名称和目标后开始。故障模式下首场失败，只允许重新生成，不能回答或提前结束。
5. 重试成功后作答，结束显示报告。刷新浏览器，通过历史恢复场次，“再练一场”保留原范围、题量、难度和重点。
6. 进入目标岗位页新增测试岗位后返回面试：下拉应刷新；按岗位训练只引用其要求，不修改 Career 当前规划。
7. 生产配置下，从主 AI 明确要求“按某岗位开始面试”，应跳到工具创建的那一场；明确要求记录真实经历后在学习记录页读到同一条记录。业务失败不自动跳页。
8. 在本模块作答/保存时，网络面板应调用 `/api/evidence/*`，而非 `/api/chat`。计划建议不会未经请求直接创建任务。

真实浏览器及真实模型验收通过前，不应对外宣称这两个模块已经全部验收完成。
