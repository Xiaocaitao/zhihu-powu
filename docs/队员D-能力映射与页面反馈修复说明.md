# Evidence 与 Interview：能力映射、历史访问与加载反馈

## 本次问题与处理

- AI 产品经理岗位的 `user_research`、`ai_product_design`、`product_iteration`、`communication`、`llm`、`ai_product_experience` 未被共享目录识别。增加六项独立能力及其明确别名；不把岗位要求等同于用户已掌握的能力。生产服务启动时沿用现有目录安装流程，无新增数据库表或跨模块写入。
- 对真正未收录的要求，后端聚合为一条带岗位能力名称的说明。前端将本场范围和可展开的评估限制分开展示。已有面试保持创建时的快照，新的能力映射用于新面试，历史报告不被追溯修改。
- 历史按钮原先只更新上方内容，缺少可见反馈和滚动定位。增加读取状态、所选行标识、题目区域定位及焦点管理；失败就地显示错误。过时的面板刷新不能覆盖新选择，切换场次时暂存未提交回答（仅当前页面内存，刷新后不保留）。
- 开始面试、提交回答、生成整场报告、保存学习记录、评估证据及生成复盘均增加加载反馈。生成期间禁用对应的重复操作，结束后恢复。结果使用短渐入动画；系统开启减少动态效果时停用动画。不模拟生成内容或进度百分比。

## 与其他模块的边界

Career 岗位查询、Shared Skills 精确解析及 Evidence 评估继续在后端衔接。模块页面仍直接调用公开 HTTP 接口；主 AI 的 13 个 Evidence 工具及导航入口保持可用。学习记录只保存真实事实，岗位仅作为用户选择的评估标准；本次不修改职业目标或学习计划。

## 手动复测

PowerShell 启动：

```powershell
$env:PREVIEW_PORT='3103'
$env:PREVIEW_GENERATION_DELAY_MS='2500'
node scripts/evidence-preview.ts
```

打开 `http://127.0.0.1:3103/`。延迟只作用于本地预览的模拟生成器，方便观察加载效果。

1. 模拟面试选择「专项能力 → AI 产品设计」，开始一题训练，检查等待动画及按钮恢复。
2. 提交回答后查看反馈与报告，再练一场。在新场次输入尚未提交的回答，点击历史中的已完成场次，应自动定位到题目区域；切回新场次，输入仍保留。
3. 学习记录保存测试内容后生成复盘；等待时再次点击不重复请求，完成后展示返回内容。
4. 在接入 Career 的环境中新建包含上述能力编码的岗位，再创建面试，确认新场次无这六项未匹配提示。其他未知能力仍应有范围限制说明。
