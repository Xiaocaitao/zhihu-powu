# Evidence & Interview 模块需求文档

对应页面：学习记录、模拟面试
模块职责：学习轨迹、项目成果、能力证据、阶段复盘、面试记录和反馈

## 1. 文档目的与依据

本文件明确模块解决的用户需求、对主 Agent 提供的工具、工具的业务输入输出、跨模块协作及验收标准。工具名称用于约定能力边界；不涉及代码、接口实现、数据库表结构、提示词或技术选型。

需求依据：

- 《成长空间模块分工.md》。
- 《工程契约与模块能力接口.md》。
- 原型 `learning-platform-prototype(3).html` 中最终生效的“学习记录”和“模拟面试”页面，以及相关页面中的联动信息。
- 本次负责人明确的职责修正：**阶段测试用于完善学习计划，归 Learning Plan，不归 Evidence & Interview。**本模块仅在需要时引用对方提供的测试结果，不负责出题、组织测试、评分或据此调整计划。原分工文档中的“阶段测验”归属以本次修正为准。

原型说明产品意图，不代表业务已实现。原型中的姓名、时间、题目、题量、能力等级和匹配度变化均为展示样例，不能作为真实用户的数据或固定结论。

## 2. 模块定位与边界

### 2.1 产品目标

让用户和主 Agent 能回答四个问题：

1. 最近实际学了什么、完成了什么、卡在哪里？
2. 有哪些成果能支持某项能力判断，哪些内容还没有得到验证？
3. 一段时间内有什么进展，下一步值得改进什么？
4. 面对目标岗位，用户在知识理解、项目说明和表达方面表现如何？

### 2.2 顶层业务抽象

| 能力 | 核心业务对象 | 主要结果 |
| --- | --- | --- |
| 学习轨迹 | 学习活动、任务变化、卡点、成果提交、计划调整的历史记录 | 可追溯的学习时间线 |
| 能力证据 | 学习成果、项目成果、材料引用、能力关联和证据评估 | 有依据的能力表现与待验证项 |
| 阶段复盘 | 指定时期或阶段内的记录与证据汇总 | 进展、困难、原因线索及改进建议 |
| 面试训练 | 面试会话、题目、回答、逐题反馈和整场报告 | 岗位相关训练及可复查的表现反馈 |

“阶段复盘”是对已有经历的回顾；“阶段测试”是学习计划模块组织的检验活动，两者不混同。

### 2.3 本模块负责

- 记录计划内和计划外的学习活动、实际投入时间、学习成果及项目贡献。
- 汇集其他模块已发生的相关业务变化，形成学习时间线。
- 管理成果材料关联、补充、修正与撤回。
- 评估成果对具体能力的支持程度，保留依据及判断局限。
- 生成和查询阶段复盘。
- 开展文字模拟面试，保存问答、进度、反馈和历史记录。
- 向其他模块提供学习事实、能力证据、面试表现及改进建议。

### 2.4 本模块不负责

- 阶段测试及其出题、作答组织、评分、测试记录维护。
- 学习任务的完成判定、任务状态维护、计划制定和计划调整。
- 全局用户画像维护、岗位要求定义、职业决策和岗位匹配度计算。
- 知识库文件上传、解析、存储和检索本身。
- 主 Agent 的全局调度、首页聚合及通用聊天记录管理。
- 首版的语音视频面试、监考、企业招聘评审、排行榜和复杂题库运营。

学习记录展示任务已完成，不代表本模块有权将任务标记为完成；面试反馈建议补 SQL，不代表本模块已经新增学习任务。

## 3. 首版用户需求

### 3.1 学习时间线

**FR-01 查看真实学习轨迹**

- 用户打开学习记录页，可以查看本周记录，并切换时间范围。
- 时间线覆盖学习活动、任务部分完成或完成、卡点反馈、成果提交、实际生效的计划调整，以及可用的面试或测试结果摘要。
- 每条记录展示发生时间、内容摘要、来源和相关对象；实际用时只有在已知时才展示，不能用任务预计时间代替。
- 支持按类型、任务或能力筛选，并查看单条记录的详情与关联材料。
- 外部结果未能获取时，说明受影响范围；不能把“未获取到”当成“没有发生”。
- 没有记录时展示空状态，允许用户通过对话记录学习或进入学习计划。

**FR-02 记录学习与项目成果**

- 用户可以通过首页对话记录学习，也可以补充已有记录的成果材料。
- 记录不强制依附学习计划；计划外学习同样可以沉淀。
- 允许记录部分完成、当前卡点和待补材料，不要求完成后才能记录。
- 项目成果包括项目目标、完成内容、本人贡献、遇到的问题及解决过程；团队项目不能把整个团队产出归为个人能力。
- 支持文字说明和多个材料引用，同一项目可以有多次阶段成果。
- 对话中只有问题、假设或未来计划时，不应自动记录为已发生的学习事实。

**FR-03 补充、修正与撤回**

- 用户可以补交截图、笔记或项目链接，修正时间、用时、描述和本模块维护的关联信息。
- 对本模块保存的错误成果，用户可以撤回；撤回保留可追溯说明，不再参与新的有效证据判断。
- 其他模块产生的任务状态、反馈和测试结果需要由来源模块修正，本模块反映其修正结果。
- 材料、内容或能力关联发生实质变化后，受影响的旧评估标明需要重新评估，不能继续作为最新有效结论。

### 3.2 能力证据

**FR-04 展示有依据的能力卡片**

- 卡片包含能力名称、证据支持的表现、依据、评估时间、未验证内容和建议验证方式。
- 区分用户自述、已提交材料、基于材料的评估、面试表现及外部测试结果。
- “有学习记录”“已上传材料”“任务已完成”均不自动等于“掌握能力”。
- “待验证”是证据状态，不是低能力等级；可以同时表达“曾有应用证据，但当前材料需要补充验证”。
- 能力表现可参考项目现有的“已接触、能够解释、能够应用、稳定掌握”等词汇，但必须说明支持范围，不能无依据升级。
- 查看指定能力时，即使暂无证据也返回明确的待验证说明；查看全部卡片时，不为用户凭空生成一整套能力地图。

**FR-05 评估成果支持什么能力**

- 保存成果与评估成果是两个业务动作，主 Agent 可以按用户意图衔接调用。
- 评估必须关联可追溯的成果、回答或来源结果，说明使用的评价要求。
- 用户自述可以作为待核实信息，不能被工具包装成已经验证的事实。
- 链接不可读取、截图缺失、内容不足时，返回材料限制及补充建议；不得声称已阅读或运行项目。
- 一份成果可以支持多个能力，每个能力分别说明依据，不能将单项表现扩展为整体岗位胜任结论。
- 多份证据不一致时同时展示差异与时间背景，不简单用最新一条覆盖全部历史。
- 本模块的证据评估供 Profile、Career 等模块参考，不直接覆盖其维护的全局结论。

### 3.3 阶段复盘

**FR-06 生成并保存阶段复盘**

- 用户点击“生成复盘”或在对话中指定时期、阶段，获得可再次查看的复盘。
- 复盘包括范围、有效记录概览、主要进展、反复卡点、成果与证据变化、下一步建议，以及所引用的记录。
- 区分已知事实、可能原因和建议；不能仅凭一次“太难”就断言用户缺少某项基础。
- 若涉及任务或计划，读取学习计划模块提供的阶段目标和实际变化，区分“建议调整”“已有调整草案”“已经生效”。
- 记录不足时说明覆盖不足；完全无可用记录时，不生成包含虚构进展的正式复盘。
- 后续重新生成形成可区分的新复盘，旧复盘保留当时的范围与依据。来源后来失效或被修正时，旧复盘提示其依据变化。

### 3.4 模拟面试

**FR-07 开始岗位相关的文字训练**

- 首版以目标岗位面试为主要场景，题目可覆盖相关知识、项目实践和表达。
- 用户可以指定已有目标岗位；没有岗位时，可明确选择某项能力或某个项目开展专项文字训练，不假设用户的目标岗位。
- 可参考用户基础和相关成果；缺少画像或项目材料时仍可进行条件允许的通用知识训练，并说明实际采用的范围。
- 开始后展示训练范围、实际难度、题量及当前题目。题量不把原型的 5 题作为不可变规则。
- 用户已有进行中的面试时应可继续；明确要求新开时创建独立面试，不能覆盖原会话。

**FR-08 逐题作答与反馈**

- 每次提交对应当前题目，保存原始回答，再给出本题反馈及下一步状态。
- 首版采用训练模式：逐题反馈，结束后再提供整场总结。
- 逐题反馈包括考察能力、回答中的有效内容、知识或逻辑问题、表达改进建议；不适用的维度不强行评价。
- 知识正确性与表达流畅度分别说明，不能因表达好就认定知识正确。
- 回答为空时不推进题目。网络重试或重复提交不能重复记录回答、重复推进题号。
- 首版已正式提交的回答保留原文，不允许通过改写历史回答提高原场成绩；再次练习形成新会话。
- 首版不要求自动追问；多轮追问列为后续扩展，避免题量、题号和完成条件含混。

**FR-09 保存、恢复与结束训练**

- 页面刷新、离开或对话中断后，可以找回已有会话、已提交回答和当前题目；首版不要求保存尚未提交的输入框草稿。
- 完成全部题目后自动结束并形成总结；用户也可提前结束。
- 面试进度与反馈生成状态分别表达。回答已保存但评估失败时，不丢失回答，也不要求重新作答。
- 提前结束只评价已回答内容；没有任何回答时说明未形成有效评价。
- 已结束的面试不能继续追加回答，用户可以据此开启新训练。

**FR-10 历史报告与改进建议**

- 用户可以按时间、岗位和会话状态查询历史面试，查看完整问答及报告。
- 整场报告包含训练范围、已答覆盖、优势、薄弱项、引用回答及可执行的练习建议。
- 首版不以单一总分或固定雷达图作为必需输出；有评分时必须说明维度、尺度和依据。
- 报告中的面试表现可以成为能力证据，必须标明来源为模拟面试；“能够解释”不能直接替代“已经实际完成项目”。
- 不同岗位、难度和考察范围的面试，不直接用总分高低判断进步；自动趋势分析列为后续扩展。
- 建议转入学习计划时，由主 Agent 联动 Learning Plan，并展示对方实际处理结果。

## 4. 工具充分性结论

原分工文档提出 6 个工具，目前属于约定中的能力，并非已实现的模块工具。它们覆盖基础查询、成果保存、面试开始与作答，但不足以支持原型和完整用户流程。

| 缺口 | 仅保留原有工具的问题 | 首版补充能力 |
| --- | --- | --- |
| 成果修改 | 无法补截图、纠错或撤回 | `update_learning_evidence` |
| 证据评估 | 保存即判定能力，或查询时偷偷产生新评估 | `evaluate_learning_evidence` |
| 阶段复盘 | “生成复盘”无对应业务能力，历史复盘无法读取 | `generate_learning_review`、`get_learning_reviews` |
| 面试恢复 | 无法读取当前题目及已有问答 | `get_interview_session` |
| 面试历史 | 只能凭已知面试标识查报告，无法找到历史会话 | `get_interview_records` |
| 主动结束 | 无法提前结束，或查询报告时隐式结束面试 | `finish_interview` |

**首版拟定 13 个主 Agent 工具：保留原有 6 个，补充 7 个。**它们覆盖记录与修正、保存与评估、生成与读取、开始与继续、完成与复盘的完整流程。

首版不再单独增加“记录项目”“补截图”“获取下一题”“查看单条学习记录”“阶段测试”等工具：项目及材料属于证据管理；下一题由作答结果或会话详情提供；记录详情由记录查询提供；阶段测试属于其他模块。

## 5. 工具的通用业务契约

### 5.1 输入约定

- 用户身份和可信来源由系统提供，主 Agent 不自行指定其他用户身份或把自述标成外部验证结果。
- 下列工具中的“标识”指已存在且用户可访问的业务对象；不得凭名称猜造标识。
- 时间范围使用明确起止时间，并按用户适用的时区解释“本周”等相对时间；结果显示实际采用的范围。
- 查询支持分页时，输入包含可选的每页数量和继续查询位置；输出说明是否还有后续内容。
- 同一工具支持“列表”与“详情”时，通过是否提供对象标识区分；不接受含混的列表筛选与详情查询组合。
- 写入只依据用户明确表达的事实、操作意图或来源模块已确认的业务变化。对不清楚的目标或关联返回待补信息，不擅自做跨模块决定。

### 5.2 输出约定

每次调用均说明：是否成功、是否实际改变记录、所属业务范围、相关对象标识、处理摘要和业务结果。重要记录应可辨别当前修订情况，避免用户修改后被旧内容覆盖。

查询只返回已有事实和评估，不因查询产生新记录、新评分或新报告。依赖暂时不可用但已有本地内容可读时，返回可用内容及缺失范围，不伪装成完整结果。

操作结果与业务对象状态分开表达。例如，“结束操作成功”不等于“反馈已经生成”。凡涉及生成，明确标识尚未生成、处理中、已完成或失败，并说明允许的后续动作。

### 5.3 共通异常与一致性要求

- 对象不存在、不可访问、输入缺失或不合法、当前状态不允许操作、内容已被他处修改、重复请求和外部依赖不可用，均须给出可理解的处理说明。
- 同一请求重试不得重复记学习时间、重复创建成果或多次推进面试。
- 外部业务变化在时间线只体现一次；其后修正应能关联原始来源，不能伪装成另一次学习行为。
- 跨模块操作允许部分成功，但必须逐项说明。例如成果保存成功、任务关联暂未完成，不能整体声称任务已更新。
- 生成失败不回滚已经保存的学习事实或回答。重试恢复同一业务操作，不创建重复对象。
- 调用写入工具不等于必须再次询问用户：用户已清楚表达的补充、作答等意图可直接执行；目标不明或会覆盖冲突内容时才需要澄清。

## 6. 主 Agent 工具输入输出

本节为业务契约，必填与可选按业务语义约定，字段类型和协议另行定义。

### T01 `get_learning_records`：查询学习时间线或记录详情

- **性质：**只读。
- **输入：**详情查询必填记录标识；列表查询可选时间范围、记录类型、任务标识、能力标识及分页条件，未指定时间时查询本周并返回实际范围。
- **输出：**记录标识、类型、摘要或详情、发生时间、已知实际用时、来源、任务或项目关联、材料状态、修正或撤回状态；列表附分页信息和数据覆盖说明。
- **规则：**默认列表不把撤回成果计入有效成果；查看其详情仍说明撤回原因。外部来源内容不可用时保留可说明的关联及限制。
- **示例：**“看看这周数据库学了什么”→ 返回相关记录、来源与真实用时；没有记录则返回空列表。
- **联动：**需要展示外部任务、卡点、调整或测试结果时，使用 Learning Plan 提供的数据。

### T02 `record_learning_evidence`：保存学习活动或成果

- **性质：**写入。
- **必填输入：**记录类型、内容说明、发生时间。项目成果还需说明本人贡献；不清楚的贡献可记录为待补充，不作已验证能力依据。
- **可选输入：**实际用时、项目关联、任务关联、能力关联、材料引用、个人反思与卡点描述。
- **输出：**保存后的记录标识、成果内容、已建立的关联、待补充信息及保存状态；涉及证据时返回证据标识和尚未评估等状态。
- **规则：**该工具保存事实，不以输入中的自评分直接生成已验证结论。任务或材料关联失败时说明部分成功及原因，不替用户猜测关联对象。
- **示例：**“昨天写了 55 分钟 API，做了一半，截图稍后补”→ 保存部分完成记录，实际用时 55 分钟，材料待补。
- **联动：**关联任务使用 Learning Plan；关联材料使用 Knowledge。用户同时要求反馈困难或更新任务时，由主 Agent 调用 Learning Plan 的对应能力，本工具不替代它们。

### T03 `update_learning_evidence`：补充、修正或撤回记录与成果

- **性质：**写入。
- **必填输入：**记录或证据标识、操作意图；修正时提供变更内容，撤回时提供原因。
- **可选输入：**补充材料、本人贡献、修正后的发生时间或用时、能力及任务关联。
- **输出：**更新后的内容、操作结果、受影响的证据评估及是否需要重新评估。
- **规则：**只修改本模块拥有的内容；外部任务、测试等内容返回应由来源模块处理的说明。不得静默改写引用旧成果的历史报告。
- **示例：**“给昨天的 API 成果补上运行截图”→ 增加材料引用，并标明该成果待重新评估。
- **联动：**Knowledge 校验材料可用性；涉及外部源记录纠错时由主 Agent 转交来源模块。

### T04 `evaluate_learning_evidence`：评估证据对能力的支持

- **性质：**生成并保存评估。
- **必填输入：**一个或多个有效证据标识、需要评估的能力范围。
- **可选输入：**岗位或任务关联，用于取得相应要求；需要关注的问题。
- **输出：**评估标识、各能力的支持结论、对应材料与理由、评估时间、覆盖限制、待验证项和补充建议。
- **规则：**缺少评价要求时可基于明确的一般能力标准评估，但说明所用标准；用户要求按某岗位标准评估而岗位要求不可用时，不冒充岗位评估。材料不足时可以保存“证据不足”的评估，不能虚构通过结果。
- **示例：**“这些 API 成果能说明我会处理 HTTP 请求吗”→ 给出已支持的表现、引用材料和尚未验证的情形。
- **联动：**Knowledge 提供材料；Career 提供岗位要求；Learning Plan 提供相关任务验收要求。对外部阶段测试仅引用原评分和范围，不重新评分。

### T05 `get_skill_evidence`：查询能力证据卡片

- **性质：**只读。
- **输入：**可选能力范围、时间范围、证据来源及分页条件；未指定能力时查询用户已有证据涉及的能力。
- **输出：**能力标识与名称、有效证据、已有评估结论及其依据、待验证项、已有验证建议、过期或待重新评估说明。
- **规则：**不因查询触发新评估。指定能力没有证据时明确返回暂无证据；对撤回或待重评内容不沿用旧结论作为当前有效判断。
- **示例：**“我数据库方面有什么能力证据”→ 返回项目或面试依据及缺口，而不是直接认定掌握。
- **联动：**向 Profile、Career、Learning Plan 和首页提供证据参考；能力标识沿用项目共享约定。

### T06 `generate_learning_review`：生成阶段复盘

- **性质：**生成并保存复盘。
- **必填输入：**明确时间范围或学习阶段标识；两者同时提供时说明以该阶段内指定时间段为范围。
- **可选输入：**关注的任务、项目、能力或复盘问题。
- **输出：**复盘标识、实际范围、记录覆盖、进展、反复卡点、成果及能力证据变化、原因线索、改进建议、引用记录及依赖缺失说明。
- **规则：**不修改学习计划。完全无记录时返回无法形成有效复盘及需要补充的内容；存在部分记录时可生成有限范围复盘并说明限制。
- **示例：**“复盘一下我这周的学习”→ 总结真实进展及困难，并区分建议与已生效的计划变化。
- **联动：**Learning Plan 提供阶段目标、相关任务、反馈和调整事实；必要时引用其已有测试结果。

### T07 `get_learning_reviews`：查询历史复盘

- **性质：**只读。
- **输入：**详情查询提供复盘标识；列表查询可选时间范围、阶段标识及分页条件。
- **输出：**复盘列表或完整内容、生成时间、覆盖范围、引用来源及来源后来发生变化的提示。
- **规则：**页面刷新读取已有复盘，不自动重新生成；无历史时返回空列表。
- **示例：**“打开上周那份复盘”→ 找到并展示原复盘，不能替换成当前数据的新总结。
- **联动：**可向首页或学习计划模块提供已保存的复盘摘要。

### T08 `start_interview`：开始模拟面试

- **性质：**创建面试会话。
- **必填输入：**明确训练范围，至少包含目标岗位、指定能力或项目之一。
- **可选输入：**难度、题量、重点关注内容；用户明确提出的新开意图。
- **输出：**面试标识、实际采用的岗位或专项范围、所参考的要求、难度、总题量、首题、会话状态及资料限制。
- **规则：**未指定难度或题量时，本模块根据可用信息确定并在开始结果中明确展示。目标不清楚时返回需补信息；已有进行中会话且无明确新开意图时返回已有会话入口，不重复创建。
- **示例：**“按我的后端实习岗位练一次面试”→ 取得已选岗位要求，创建会话并返回首题；多个岗位且无法确定时先澄清目标。
- **联动：**Career 提供岗位要求，Profile 提供基础信息，Knowledge 与本模块证据提供项目材料。依赖缺失时不擅自把岗位面试改成另一类训练。

### T09 `get_interview_session`：读取或恢复面试

- **性质：**只读。
- **必填输入：**面试标识。
- **输出：**训练范围、开始时间、会话状态、题量、已答进度、已提交问答、已有逐题反馈、当前待答题或结束说明、报告状态。
- **规则：**读取不创建新题、不重新评分、不推进进度。面试进行中不展示未来未作答题目的参考答案。
- **示例：**“继续刚才那场面试”→ 根据已找到的会话标识恢复到当前待答题。
- **联动：**无需强制重新读取岗位或画像；恢复时沿用本场开始采用的训练范围。

### T10 `submit_interview_answer`：提交回答并推进训练

- **性质：**保存回答并产生本题反馈。
- **必填输入：**面试标识、当前题目标识、回答正文。
- **输出：**回答标识、保存结果、反馈或反馈状态、已答进度、下一题或整场已结束状态。
- **规则：**只接受当前可回答题目。相同提交重试返回原保存结果；同一已答题提交不同内容时拒绝改写并说明原因。反馈失败仍保留回答；重复原提交可恢复未完成的反馈处理，不重复推进。
- **完成规则：**最后一题有效提交后，自动结束面试并触发整场总结；总结未完成时明确报告状态。
- **示例：**用户提交项目问题的回答 → 保存原文，指出回答中的具体问题，并返回下一题。
- **联动：**使用本场确定的要求和可用材料评价，不由主 Agent 在输入中指定“正确”“满分”等评估结论。

### T11 `finish_interview`：提前结束或恢复未完成的总结

- **性质：**结束会话并形成整场报告。
- **必填输入：**面试标识。
- **可选输入：**提前结束原因。
- **输出：**最终会话状态、已答和未答范围、报告标识及报告状态、后续可执行动作。
- **规则：**用户明确表达结束意图后结束。已结束且报告完成时返回已有结果；报告失败时可重试本工具恢复总结，不创建新会话或覆盖有效报告。总结应处理或明确标注尚未完成的逐题评估。
- **示例：**“今天练到这里，帮我总结”→ 结束当前面试，仅评价已经回答的部分。
- **联动：**报告保存后，其有依据的表现可由本模块纳入能力证据；向学习计划仅提供建议，不直接创建任务。

### T12 `get_interview_feedback`：查询已有面试反馈

- **性质：**只读。
- **必填输入：**面试标识。
- **可选输入：**题目标识，用于查询单题反馈。
- **输出：**本题反馈或整场报告、评价维度、引用回答、优势与问题、改进建议、覆盖限制、生成状态。
- **规则：**报告尚未生成、正在生成或失败时分别说明；查询不触发结束、重评或重试，失败时提示可用的恢复动作。
- **示例：**“刚才面试主要差在哪里”→ 读取报告中的问题和回答依据。
- **联动：**主 Agent 可据建议继续联动 Learning Plan；读取本身不改变计划或画像。

### T13 `get_interview_records`：查询历史面试

- **性质：**只读。
- **输入：**可选时间范围、岗位、专项能力、会话状态和分页条件。
- **输出：**面试标识、训练范围、开始与结束时间、状态、已答情况、报告状态及已有摘要，附分页信息。
- **规则：**可筛选进行中会话；找到多个结果时不得擅自认定用户要恢复其中一场。无记录时返回空列表。
- **示例：**“看看我之前做过的后端面试”→ 返回相关会话，再通过详情或报告工具查看。
- **联动：**首页可以使用进行中会话或最近报告摘要，不需要单独新增主 Agent 汇总工具。

## 7. 面向其他模块的协作能力与数据需求

### 7.1 本模块向外提供什么

其他模块可使用与上述工具一致的业务能力，不需要通过一次聊天来获取结果，也不另设一套业务判断。

| 使用方 | 本模块提供的业务能力 | 使用限制 |
| --- | --- | --- |
| Agent/Core | 全部 13 项工具；学习时间线、最新复盘、能力证据和面试摘要查询 | 主 Agent 负责跨模块顺序与对用户说明，不能绕过归属直接改业务数据 |
| Profile | 能力证据与面试表现查询 | Profile 自行决定是否及如何更新画像 |
| Career | 指定能力的证据、项目成果和面试表现查询 | Career 自行完成岗位差距与匹配分析 |
| Learning Plan | 学习记录、阶段复盘、成果评估及面试改进建议查询 | 计划模块维护任务验收、测试和计划调整 |
| Learning Plan 等来源模块 | 将已确认的业务变化关联到学习轨迹，并传达后续修正 | 来源可信性由系统保证；主 Agent 不能伪造“来源模块已确认” |

“接收来源变化”是模块协作需求，不额外暴露一个让模型自由编造外部业务事件的工具。与自主记录的时间线项应保留不同来源，同一事实不得重复计时或重复计为成果。

### 7.2 需要其他模块提供什么

| 来源模块 | 所需业务数据或能力 | 对应用途 | 是否必须及缺失处理 |
| --- | --- | --- | --- |
| Learning Plan | 任务详情、所属计划或阶段、状态、预计成果、验收要求 | 任务关联、时间线、成果评估、复盘 | 任务关联或按任务标准评价时必须；计划外学习不依赖 |
| Learning Plan | 已发生的进度变化、困难反馈、调整记录和生效状态 | 时间线和复盘 | 缺失时显示覆盖不足，不从当前任务状态虚构历史 |
| Learning Plan | 已有阶段测试的结果摘要、考察能力、评分依据和原始结果入口 | 经用户需要在轨迹或证据中引用 | 可选；不为读取结果而发起测试，也不在本模块重新评分 |
| Career | 用户已选目标岗位、岗位能力标识、要求及适用背景 | 岗位面试、岗位相关证据评估 | 岗位定向训练必须；专项训练可不依赖 |
| Profile | 必要的基础信息、学习背景及已知目标 | 辅助确定训练难度与上下文 | 可选；缺少时使用用户本次明确提供的信息，不编造画像 |
| Knowledge | 用户材料的标识、可访问状态、可用内容及可引用位置 | 成果引用、证据评估、项目面试 | 材料评估时必须；只保存文字自述可以不依赖 |
| Agent/Core | 当前用户、可信来源、当前交互关联 | 确定数据归属及联系原始对话 | 必须；缺少可靠身份不能读取或保存个人业务数据 |

### 7.3 是否需要读取其他模块的表

**需要其他模块的数据，但不直接读取或修改其他模块的表。**本需求只约定数据内容与归属，遵循现有工程契约，通过对方提供的业务查询或操作能力取得结果。

- 本模块拥有：自主学习记录、项目成果、材料关联、证据评估、复盘、面试会话、问答与面试反馈。
- 本模块引用：用户画像、岗位要求、任务与阶段、计划调整、阶段测试结果、知识库材料。
- 引用外部对象时保留其来源，避免形成另一套可独立修改的任务、画像或测试记录。
- 历史面试和复盘保留当时采用的范围、要求与依据；外部数据更新后，不应把旧报告伪装成按新要求生成的报告。
- 具体表名、关联方式和数据同步方法属于后续技术文档，不在本次需求中决定。

### 7.4 需要团队补齐的协作约定

现有分工中的工具只是建议，尚不能证明以下能力已经存在。这些是后续联调依赖，不属于本模块已完成的功能：

1. Learning Plan 能否查询指定任务、历史反馈、计划调整及修正，而不仅是当前有效计划。
2. Learning Plan 如何提供阶段测试结果的权威摘要，以及哪些内容允许作为能力证据引用。
3. Career 是否能提供指定岗位的完整能力要求，项目如何统一能力标识与能力名称。
4. Knowledge 能提供哪些材料的实际内容，特别是运行截图、外部项目链接及失效材料的状态。
5. 来源变化如何保证只形成一次学习轨迹，以及来源修正、撤回后如何反映到引用方。

上述能力未齐备时，本模块可先满足自主记录、已有文字成果评估和用户明确指定范围的文字训练；涉及缺失依赖的关联、评价或复盘必须返回限制，不假装已联通。

## 8. 典型业务闭环

### 8.1 完成任务并提交成果

用户说明完成任务并提交材料 → 主 Agent 确认具体任务 → Learning Plan 处理任务状态或验收 → 本模块记录成果并关联来源 → 根据需要评估成果 → 学习记录页显示真实状态与证据。

任务是否完成以 Learning Plan 的实际结果为准。成果保存成功但任务更新失败时，分别说明结果，不重复提交已保存成果。

### 8.2 记录困难并生成复盘

用户反馈困难 → Learning Plan 记录学习反馈 → 时间线关联该反馈 → 用户请求复盘 → 本模块读取轨迹、阶段目标及已有证据 → 形成复盘与建议 → 如需调整，由主 Agent 联动 Learning Plan → 调整成功后再显示实际调整记录。

### 8.3 补充材料并更新证据

用户补交项目材料 → Knowledge 提供可用引用 → 本模块补充原成果 → 旧评估标明待重评 → 主 Agent 根据用户意图调用证据评估 → 能力卡片展示新的依据及仍未验证的内容。

### 8.4 面试后完善学习计划

取得用户指定岗位要求 → 开始面试 → 逐题作答与反馈 → 自动或主动结束 → 保存整场报告并沉淀面试证据 → 主 Agent 向 Learning Plan 提供薄弱项及练习建议 → 由 Learning Plan 决定调整内容。

本流程不启动阶段测试；如果学习计划模块后续认为需要测试，由其自行负责。

## 9. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 用户没有学习记录 | 时间线为空并说明可执行入口，不出现原型样例 |
| AC-02 | 记录计划外学习 | 无任务标识仍可保存，并显示正确时间、内容及已知实际用时 |
| AC-03 | 任务预计 2 小时但实际用时未知 | 不把 2 小时展示为实际学习时长 |
| AC-04 | 同一任务变化或同一成果重复送达 | 时间线、实际用时及成果数量不重复累计 |
| AC-05 | 项目部分完成、截图未补 | 可以保存，并显示部分完成与材料待补，不显示验证通过 |
| AC-06 | 补充或撤回影响结论的材料 | 保留变更说明，旧评估不再作为当前有效结论，允许重新评估 |
| AC-07 | 只提供“我已经掌握数据库”的自述 | 记录来源为自述，不能据此展示已验证掌握 |
| AC-08 | 查询证据或反馈 | 不生成新评估、新记录或新报告 |
| AC-09 | 请求阶段复盘 | 返回实际范围、引用依据、进展与建议；没有依据时不虚构总结 |
| AC-10 | 复盘提出拆分任务但计划未调整 | 显示建议状态，不能显示计划已调整 |
| AC-11 | 查询阶段测试结果 | 只引用 Learning Plan 的已有结果，不出现本模块出题或重新评分 |
| AC-12 | 未指定岗位或专项范围就开始面试 | 返回需补充目标的信息，不套用原型的后端岗位 |
| AC-13 | 提交回答后重复请求或刷新 | 回答只保存一次、进度只推进一次，刷新可恢复当前会话 |
| AC-14 | 回答已保存但评估失败 | 明确保存成功与评估失败，可恢复处理，不要求重新作答 |
| AC-15 | 最后一题提交或用户提前结束 | 正确结束并生成报告；提前结束标明未考察范围 |
| AC-16 | 面试结束但报告生成失败 | 查询说明状态，重试结束工具可恢复总结且不创建新会话 |
| AC-17 | 岗位要求后来发生变化 | 历史面试仍显示本场采用的要求与范围，不静默改写结论 |
| AC-18 | 请求查看他人的记录或引用不可访问材料 | 不泄露内容，不把该材料作为有效依据 |
| AC-19 | 外部模块暂时不可用 | 返回可用结果和缺失范围，不把不完整查询声称为完整报告 |
| AC-20 | 面试建议补学数据库 | 本模块仅输出建议，只有 Learning Plan 操作成功才显示计划已变化 |

## 10. 未来扩展空间

首版保留稳定的业务边界，后续按真实需求扩展，不提前承诺下表功能，也不为每个假设新增主 Agent 工具。

| 方向 | 首版保留的业务空间 | 后续可能新增的能力 |
| --- | --- | --- |
| 更多成果形式 | 一份成果可关联多份材料，区分材料来源与可评估范围 | 代码仓库评审、作品集整理、成果导出 |
| 项目持续迭代 | 同一项目可有多次成果提交，保留本人贡献和历史依据 | 项目成长对比、里程碑复盘 |
| 更多评估依据 | 将事实、材料、评估结论分开，并标明来源 | 导师评价、人工复核、多来源争议处理 |
| 面试追问 | 保留题目、回答和考察能力的关联 | 按回答追问、动态调整题目，届时明确追问与题量关系 |
| 不同训练方式 | 会话明确训练范围与规则，首版只承诺逐题反馈的文字训练 | 整场结束后统一反馈的模拟模式、限时训练、语音视频 |
| 成长趋势 | 历史报告保留时间、难度、要求及考察范围 | 在可比条件下分析进步趋势和重复薄弱项 |
| 针对薄弱项复练 | 报告保留问题、能力和建议的对应关系 | 从报告发起专项复练、比较同类回答 |
| 与计划更紧密联动 | 输出可引用的改进建议，计划修改权仍归 Learning Plan | 跟踪建议是否被采纳及后续任务效果 |

扩展时遵循三条原则：

1. 不改变已有工具的基本业务含义，例如查询不转为生成、保存不隐含通过验证。
2. 新增可选能力不能让旧记录失去可读性；旧数据缺少的信息明确显示未知，不补造历史。
3. 阶段测试仍属于 Learning Plan；未来引用更多测试结果也不改变本模块的职责归属。
